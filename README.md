# ML in GameDev 🎮

Учебный ML-проект по прогнозированию пользовательской активности в мобильной игре.

Цель проекта — по поведению пользователя в начальный период определить, сколько часов он проведёт в игре в течение следующего месяца.

В качестве исходных данных использовались реальные агрегированные данные мобильной игры **Gangstar: Криминальная война**, собранные с помощью **Яндекс AppMetrica**.

---

## 📌 Постановка задачи

Для каждого пользователя известен набор признаков, характеризующих его игровую активность.

Необходимо построить регрессионную модель:

\[
\hat{y} = f(x)
\]

где:

- `x` — признаки пользователя;
- `y` — количество часов, проведённых пользователем в игре за следующий месяц.

---

## 📊 Данные

Исходные данные представляли собой логи событий из **Яндекс AppMetrica**.

Изначальный датасет содержал более **73 миллионов событий**. После обработки были сформированы данные примерно для **68 544 пользователей**.

Основные поля исходных логов:

- `appmetrica_device_id` — идентификатор пользователя;
- `event_name` — тип события;
- `event_json` — дополнительные параметры события;
- `event_datetime` — время события;
- `event_timestamp` — UNIX timestamp;
- `session_id` — идентификатор игровой сессии.

Технические характеристики устройств и географические признаки были исключены, поскольку в рамках исследования они практически не улучшали качество линейных моделей.

## 🧩 Признаки

После агрегации событий был сформирован набор пользовательских признаков.

| Признак | Описание |
|---|---|
| `days_since_installation` | Количество дней с момента установки |
| `avg_interval_between_sessions` | Средний интервал между сессиями |
| `user_rating` | Оценка игры пользователем |
| `has_rating` | Ставил ли пользователь оценку |
| `total_events` | Общее количество событий |
| `max_weapon_level` | Максимальный уровень оружия |
| `unique_items` | Количество уникальных предметов |
| `unique_sessions` | Количество уникальных сессий |
| `active_days` | Количество активных дней |
| `unique_event_types` | Количество уникальных типов событий |
| `total_ads` | Количество рекламных событий |
| `percentage_ads` | Доля рекламных событий |
| `total_boss` | Количество событий, связанных с боссами |
| `percentage_boss` | Доля событий, связанных с боссами |

Для обучения использовалась логарифмированная целевая переменная:

```python
log_total_time_in_game = np.log1p(total_time_in_game)
```

Это позволило уменьшить влияние пользователей с аномально большим временем игры.

## 🔎 EDA

В процессе разведочного анализа данных было обнаружено сильно асимметричное распределение игрового времени.

Небольшая часть пользователей имела чрезвычайно высокие значения целевой переменной, поэтому было применено преобразование `log1p`.

Это помогло уменьшить влияние экстремальных значений и улучшить качество линейных моделей.

## 🚨 Детекция выбросов

В проекте исследовались три метода обнаружения аномалий.

### IQR

Метод межквартильного размаха:

\[
IQR = Q_3 - Q_1
\]

Оптимальный найденный коэффициент:

```text
k = 3.1
```

### Isolation Forest

Использовался для поиска многомерных аномалий.

Оптимальный параметр:

```text
contamination = 0.00006
```

### Local Outlier Factor

LOF определяет аномальные объекты по локальной плотности наблюдений.

Оптимальный параметр:

```text
contamination = 0.044
```

## 📈 Результаты

На исходных данных модели показали качество примерно:

```text
R² ≈ 0.808
```

После последовательной обработки выбросов:

```text
IQR + Isolation Forest + LOF
```

были получены следующие результаты:

| Метрика | Значение |
|---|---:|
| R² | **0.8108** |
| RMSE | **1.025** |
| MAE | **0.693** |

Наиболее значимыми признаками оказались:

- `unique_event_types`;
- `percentage_boss`;
- `active_days`.
